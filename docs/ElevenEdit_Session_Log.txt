ELEVEN EDIT — SESSION LOG (append-only scratchpad)
===================================================================
Purpose: the ONE place provisional, unconfirmed, or in-progress findings
live during a work session. Newest entry on top. Safe to be messy and even
contradictory — nothing here is treated as truth until it is promoted.

TRUTH LIVES ELSEWHERE:
  ElevenEdit_Technical_Reference.txt — confirmed protocol/hardware facts
  ElevenEdit_Primer.txt              — project orientation & app state
Confirmed facts are EDITED IN PLACE in those two docs. This log is never a
substitute for them and is never superseded by a dated copy.

HOW AN ENTRY GRADUATES:
  1. Add findings here as you work (any state: idea, tried-X-got-Y, confirmed).
  2. When a finding is CONFIRMED, promote it: edit the value directly into the
     Technical Reference (or Primer), then mark the log entry [FOLDED IN].
  3. [FOLDED IN] entries can be deleted once the merge is verified. The log
     should trend back toward empty.

A FACT IS EITHER:
  - confirmed  -> lives in a main doc, edited in place, not here; or
  - provisional -> lives here.
Never both. Never a third dated file.

AREA:        To Amp Source / CMD 0x37 (3rd attempt — the brick command)
FINDING:     Our CMD 0x37 send has ALWAYS carried one extra byte. The real
             message the Avid editor sends is 9 bytes:
                 F0 13 0B 0F 00 37 [slot] [val] F7
             We were sending 10:
                 F0 13 0B 0F 00 37 07 [slot] [val] F7
             The 0x07 is a USB-MIDI packet-framing byte (CIN header of the
             final 4-byte packet, 0x07 = "SysEx ends, 3 data bytes"), misread
             off the 7/17 capture as payload. Sending it shifts everything
             over one: the rack reads slot=0x07 (invalid — only 0x00/0x01
             exist). That single byte explains BOTH open mysteries — why the
             source never moved (garbage slot) AND why it bricked (bad index
             into a 2-entry ROUTING table = the "malformed routing" the
             investigation brief hypothesised). Identical bug class to the
             CMD 0x0D Stereo/Mono framing byte already fixed in code.
             ALSO: the editor sends NO CMD 0x3A query before a change (six
             changes, zero queries in the capture). The "must query first or
             it asserts" rule was a side effect of the malformed write, not a
             real prerequisite. Source is now sent bare, matching Avid.
EVIDENCE:    93ee3c7d-To_Amp_Captures_Opus_Session.pcapng (USBPcap, Win10).
             6 source changes, each an OUT + a HW echo. Decoded by hand in
             Python (pcapng -> USB-MIDI CIN reassembly). Move 1 (ToAmp1->Amp

AREA:        To Amp Source RESO + "Rig Out No Cab" (CMD 0x3F, 0x38)
FINDING:     Capture of the HW front-panel driving To Amp source with RESO.
             (a) RESO is its own command CMD 0x3F, broadcast form
                 F0 13 0B 0F 02 3F [state] F7  (01=on, 00=off). No slot byte.
                 Reaches our MIDI path — app logged UNHANDLED CMD 0x3F.
                 *** RESO IS NOT A CAB BYPASS (Charlie, 2026-08-29). *** It taps
                 the amp block's output PRE-CABINET to a hardware output (on an
                 Amp Output source); the cab can stay ENABLED in the chain (the
                 rig output still gets the cab). It changes the amp-out TAP
                 POINT, it does not disable the cab. Distinct from 0x38 below,
                 which IS a true global cab bypass. RESO is GLOBAL: the byte
                 carries only [state], no position/output address (if it were
                 per-position it would need an address byte like 0x37's [slot]);
                 confirmed twice — the address-less byte AND Charlie's panel
                 test (set it in any of the 4 spots, all 4 mirror the one
                 value). Its EFFECT is conditional (relevant only when a source
                 feeds amp-out), but the stored flag is a single global on/off.
             (b) The HW's "5th source option" Rig Out No Cab is NOT a new 0x37
                 value. Stepping Rig Output -> Rig Out No Cab emits NO new 0x37;
                 instead CMD 0x38 (Global Cabinet Bypass, already in Sec 18)
                 F0 13 0B 0F 02 38 [state] F7 (01=No Cab / bypass on, 00=off).
                 So source stays 4 values (0x37 val 0-3); "Rig Out No Cab" =
                 Rig Output (val 3) + global cab bypass on. Likely the same cab
                 bypass state the CAB block already tracks.
             (c) Both 0x3F and 0x38 are 8-byte [state]-only — NEITHER carries a
                 ToAmp1/2 slot byte (unlike 0x37's [slot][val]).
             (d) Incidental: each routing change also re-broadcasts amp param
                 0x11 paramLo 0x05 (query+resp) — side effect, ignore.
