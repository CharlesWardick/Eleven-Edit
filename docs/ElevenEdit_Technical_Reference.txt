1. ARCHITECTURE & TRANSPORT
===================================================================

CONFIRMED WORKING ARCHITECTURE (supersedes all earlier transport designs):

  ElevenRackBridge.jar  <->  ws://localhost:57121  <->  Electron UI
         |
   javax.sound.midi
         |
   Eleven Rack USB
     IN:  "Eleven Rack No details available"  (Vendor Specific interface)
     OUT: "Eleven Rack External MIDI Port"    (standard MIDI interface)

WHY JAVA: The Eleven Rack's "Vendor Specific" USB interface carries all
SysEx traffic. Java's javax.sound.midi sees ALL Windows MIDI ports,
including the "No details available" Vendor Specific port. node-midi,
Web MIDI, and MIDI-OX see only 3 standard ports and miss it. Confirmed by
direct testing. ElevenHack (2013) uses this same javax.sound.midi approach.

PORT AUTO-DETECT (case-insensitive):
  IN  = name contains "Eleven" AND "No detail"
  OUT = name contains "Eleven" AND "External"
Typical Windows enumeration: IN=port 7, OUT=port 5 (do not hardcode indices;
match by name).

BRIDGE PROTOCOL (JSON over WebSocket):
  CLIENT -> BRIDGE: {"cmd":"connect","inPort":7,"outPort":5}
                    {"cmd":"send","hex":"F0 13 0B 0F 01 01 F7"}
  BRIDGE -> CLIENT: {"type":"midi_in","hex":"F0 13...","bytes":[...]}
  First byte auto-detects SysEx (0xF0) vs short message (CC/PC).
  Shutdown: write "SHUTDOWN\n" to bridge stdin. A forceful kill
  (taskkill /F) skips JVM shutdown hooks on Windows and can leave orphan
  processes.

FRAMING — IMPORTANT: On this MIDI-layer path the app sees clean SysEx:
  F0 13 0B 0F [dir] [cmd] ... F7  — pure 7-bit, NO 0x04 framing.
  The 0x04 device-address byte and the "0x04 per 3 bytes" framing described
  in old raw-USB (node-usb / Wireshark) research apply ONLY to the raw
  Vendor Specific endpoint. javax.sound.midi handles that layer for us.
  Never insert or strip 0x04 framing in application code. (See Section 22
  conflict C1 for how this reconciles the two research eras.)

ENVIRONMENT:
  Electron ^25.0.0, build with electron-builder --win --x64.
  No node-midi, no electron-rebuild, no node-usb dependency.
  Java: bridge source is Java 8 compatible (compile --release 8);
  JDK 21 (Temurin) used for compile, JRE sufficient at runtime.
  Windows 10. npm start has never worked in this environment — always
  build the EXE for testing.

REQUIRED AVID DRIVER: v1.1.12 (confirmed). Solid, current, fully featured,
  and what the working Java-bridge build runs on. The older v1.0.11 requirement
  came from the abandoned node-usb research and does NOT apply to this path.
  (See Section 22 conflict C2.)

SLOT MATRIX: 26 letters x 4 = 104 user slots (A1–Z4, slot index 0–103).
  bank = Math.floor(slot/4), num = slot%4, label letter = BANKS[bank].
  (Note: one source uses slot/24 for a different bank grouping — see C7.)
  After Z4: factory presets (read-only).


===================================================================
2. SYSEX WIRE FORMAT
===================================================================

All messages:  F0 13 0B 0F [dir] [cmd] [data...] F7
  Manufacturer ID: 0x13 0x0B (Avid/Digidesign)
  Device ID:       0x0F  (0x0E occasionally noted in ElevenHack source)

DIRECTION BYTE:
  0x00 = SNDSET  — we write/command to hardware
  0x01 = REQU    — we request data from hardware
  0x02 = ASYNC   — hardware sends an unsolicited state update
  0x12 = RESPOND — hardware responds to one of our REQU queries

REQU LENGTH (confirmed 7/9, 18 commands in real Avid traffic):
  Every bare REQU is exactly 7 bytes: F0 13 0B 0F 01 [cmd] F7. No trailing
  bytes. (CMD 0x11 REQU is the exception: it carries paramLo — see Sec 3.)

RESP vs ASYNC PAYLOAD OFFSET (confirmed 7/9):
  RESP to our own REQU (dir=0x12) has NO slot byte; payload starts at
  byte 6. An ASYNC broadcast (dir=0x02, e.g. hardware save) has a slot byte
  at position 6; payload starts at position 7. This offset difference is
  handled by the SEND_PATCH decode path.


===================================================================
3. CMD 0x11 — LIVE PARAMETER READ/WRITE
===================================================================

The single most important command. Reads/writes any parameter on the amp
block in real time. TWO receive formats + one send format (resolved 7/16).

FORMAT A — ASYNC broadcast (hardware -> us, spontaneous):
  F0 13 0B 0F [dir] 11 [currentParamHi] [paramLo] [v0] 00 00 00 00 F7
    data[6]=currentParamHi, data[7]=paramLo, data[8]=v0
  Fires when: any parameter changes from any source (HW knob turned, or the
  hardware echoing a value we just sent). Used for tone knobs, gate, amp out,
  amp select, cab/mic/axis/breakup live updates, bypass changes.

FORMAT B — RESP to our explicit REQU:
  F0 13 0B 0F 12 11 04 [currentParamHi] [paramLo] [v0] 00 00 00 00 F7
    data[6]=0x04 (fixed), data[7]=currentParamHi, data[8]=paramLo, data[9]=v0
  Fires when: we send a REQU query for a specific parameter.
  NOTE: This 0x04 at data[6] is REAL SysEx content, not USB framing. Earlier
  research confused it with the USB 0x04 framing byte (see C1).

SEND (our app -> hardware):
  F0 13 0B 0F 00 11 [currentParamHi] [paramLo] [v0] 00 00 00 00 F7
  Hardware accepts Format A (no 0x04) for ALL params including cab/mic, then
  echoes back as Format A ASYNC. v1–v4 = 0x00 confirmed for all writes.

REQU (query one parameter):
  F0 13 0B 0F 01 11 07 [paramLo] F7
  The 0x07 here is a broadcast/wildcard instance the firmware resolves to
  the current block; hardware replies as Format B with the real
  currentParamHi filled in.

UNIVERSAL paramLo VALUES (identical for all 33 amps, all sessions):
  0x03 = Amp Out Level
  0x04 = Gate Threshold
  0x05 = Gate Release
  0x06 = Amp Bypass        (live only; v0 check: 0x40=active, 0x3F=bypassed)
  0x0E = Bright toggle     (live: v0=127=ON, v0=0=OFF)
  0x0F = Amp Select        (raw v0 — NOT run through the (v+64)%128 formula)
  0x14 = Cab Bypass        (v0: 0x40=active, 0x3F=bypassed)
  0x15 = Cab Type          (non-standard v0 — lookup table, Section 8)
  0x16 = Mic Type          (non-standard v0 — lookup table, Section 8)
  0x17 = Mic Axis          (v0: 0x3F=On-Axis, 0x40=Off-Axis — see C4)
  0x18 = Speaker Breakup   (standard continuous 0–127)

Tone knob paramLo values are PER-AMP — see Section 11.

CRITICAL — paramLo is NOT derived from the Avid XML sldX key name above
0x09. sldF -> paramLo 0x10, sldG -> paramLo 0x11 (NOT 0x0F/0x10 as the
letter positions would imply). Wireshark is the source of truth for
paramLo; XML is the source of truth for knob labels and tfxKey names only.
(This corrects the June research; see C3.)

DO NOT send CMD 0x11 before currentParamHi is set (<=0): causes a HW assert.


===================================================================
4. currentParamHi — RUNTIME HANDLE
===================================================================

currentParamHi is a runtime handle the firmware assigns to the amp block on
each patch load. It IS the instance byte in every CMD 0x11 message for that
patch. It changes every firmware session and varies by slot position. It
CANNOT be predicted, hardcoded, or read from the TFX body.

SOURCE: data[i+2] — the third byte of the typeA=0x07 triplet in the CMD 0x21
chain map. Triplet structure at data[6+]: [typeA][mid][third]. typeA=0x07 =
amp block; its third byte = currentParamHi. DO NOT change the data[i+2]
offset — confirmed correct across many captures.

Confirmed via round-robin capture (single session):
  A2: typeA=0x07 third=0x10 -> CMD 0x11 instance=0x10
  A1: typeA=0x07 third=0x1E -> CMD 0x11 instance=0x1E
  J2: typeA=0x07 third=0x2C -> CMD 0x11 instance=0x2C
Same patch across different sessions: 0x03, 0x74, 0x21, 0x2B — varies each time.

IMPLEMENTATION:
  Read from CMD 0x21 on EVERY patch navigation; store as currentParamHi.
  Use as the instance byte in all CMD 0x11 sends.
  Filter incoming CMD 0x11 by instance === currentParamHi.
  Reset to -1 on disconnect.

*** CHAIN-REORDER HAZARD ***
  currentParamHi is POSITION-DEPENDENT. Moving the amp (or cab) block to a
  different chain position makes the firmware assign a new handle on next
  load. Sends using a stale handle hit whatever block now sits at that
  position — confirmed to corrupt gate parameters when the amp was moved.
  All CMD 0x11 sends assume the DEFAULT chain order. Amp/Cab bypass toggle
  is disabled for exactly this reason (see Section 20 / C5).

  FUTURE FIX (prerequisite for bypass toggle and chain reorder):
  The CMD 0x21 chain map contains a triplet for EVERY block, not just the
  amp. Identify the typeA value for each block type (dist, cab, mod, delay,
  fx1, fx2, ...) with one capture, store each block's paramHi per patch nav,
  then send to any block with its correct handle regardless of position.
  The CMD 0x21 parsing infrastructure already exists.

===================================================================
6. FULL COMMAND REFERENCE (0x00–0x50)
===================================================================

Legend: [SEND]=we can send it, [RECV]=hardware broadcasts it,
[DEAD]=receive-only, no send path exists on any known interface.

CMD 0x00 — Bulk TFX (patch body). Hardware broadcasts full 7-bit-encoded
  patch body on hardware-initiated save. Auto-captured to disk. [RECV]
CMD 0x01 — SEND_PATCH / bulk write. Send = load body to HW memory
  (Section 16). REQU (dir=0x01) = pull current slot's body back. [SEND/RECV]
CMD 0x02 — Current Rig Number. Send selects a slot; broadcast/RESP reports
  current slot. Used in save + navigation. [SEND/RECV]
CMD 0x03 — Save Rig (commit to slot). Part of save sequence (Section 15). [SEND]
CMD 0x04 — Rig Get/Set Name (address-based). Used in save; also a cheap
  names-only bank scan path. [SEND/RECV]
CMD 0x05 — Patch Name. Broadcast = null-terminated ASCII name; send = set
  current rig name (plain ASCII, no 7-bit encoding, no framing, max 16
  chars). [SEND/RECV]
CMD 0x07 — Rig Volume knob broadcast. F0 13 0B 0F 02 07 [v0] 00 00 00 00 F7.
  v0 decoded as CMD 0x11. Range val=0 -> -24.0 dB, val=127 -> 0.0 dB.
  REQU form reads current value. [SEND via CC17 / RECV via 0x07]
CMD 0x0D — Stereo/Mono broadcast. F0 13 0B 0F 02 0D 06 [val] F7,
  val 0x01=Stereo, 0x00=Mono. HW front panel only, no MIDI send path. [DEAD-send]
CMD 0x11 — Live parameter read/write. See Section 3. [SEND/RECV]
CMD 0x20 — Effect Description (per-effect query). Effect string ID at byte 7,
  name at byte 25. [SEND/RECV]
CMD 0x21 — Chain Map / Rig Description. F0 13 0B 0F 01 21 F7 -> triplets
  [typeA][mid][third]. typeA=0x07=amp block; third=currentParamHi. Fires on
  every patch load and on chain changes. [SEND/RECV]
CMD 0x22 — Effect Count. [SEND/RECV]
CMD 0x34 — True Z impedance broadcast. Global, front-panel only. Auto-
  broadcasts on amp/cab model change (val=0x7E=Auto in that context). [DEAD-send]
CMD 0x36 — Output Volume. F0 13 0B 0F [dir] 36 [outSel]... See Section 18.
  outSel 0x00=Main, 0x02=To Amp1, 0x03=To Amp2, 0x04=Unit Vol, 0x06=query.
CMD 0x37 — To Amp Source. *** DANGER — factory reset. Do NOT send. Sec 18/20 ***
CMD 0x38 — Global Cabinet Bypass. Global override. Front-panel only. [DEAD-send]
CMD 0x3B — Global Mute. F0 13 0B 0F 02 3B 01 [val] F7. Front-panel only. [DEAD-send]
CMD 0x3D — Input Selector broadcast. F0 13 0B 0F 02 3D [val] F7 (value at
  data[6], NOT data[7]=F7). Values: 0x00=Guitar, 0x02=Mic, 0x03=Line L,
  0x04=Line R, 0x05=Line L+R, 0x06=Dig L, 0x07=Dig R, 0x08=Dig L+R,
  0x12=Re-Amp. Broadcast on input change only (not startup/patch change).
CMD 0x40 — Tuner. See Section 9. [SEND/RECV]
CMD 0x41 — Tuner companion broadcast. Safe to ignore.
CMD 0x50 — Version/capabilities query. Request data=0x05; response
  04 03 14 29 (likely firmware version). [SEND/RECV]

Startup commands seen only in Avid editor USB capture (purpose unknown,
not required by Eleven Edit): 0x08, 0x0A, 0x35, 0x39, 0x3A, 0x3C.


===================================================================
7. VALUE ENCODINGS
===================================================================

CONTINUOUS KNOBS (CMD 0x11, 0x07, 0x36) — single-byte offset binary:
  DECODE: if v0 >= 0x40 -> val = v0 - 0x40   (range 0–63)
          if v0 <  0x40 -> val = v0 + 64     (range 64–127)
  ENCODE: v0 = (targetV127 + 64) % 128
  val 0–127 maps to 0.0–10.0 on display.
  Sentinels: min = 0x40 00 00 00 (val 0); max = 0x3F 7F 7F 7F (val 127).

TOGGLES (Bright, live) — do NOT use the continuous decode:
  Live CMD 0x11: v0=127=ON, v0=0=OFF.
  In TFX body: raw 0=OFF, 1=ON (see Section 13 toggle note).

BYPASS (amp & cab, live) — check v0 DIRECTLY, do not decode:
  v0=0x40 = active,  v0=0x3F = bypassed.

MIC AXIS (live) — check v0 directly:
  v0=0x3F = On-Axis,  v0=0x40 = Off-Axis.   (Corrected 7/16 — see C4.)

AMP SELECT (paramLo 0x0F): raw v0 used directly (NOT the (v+64)%128 formula).
  Full v0->amp table is AMP_SELECT_LIST in protocol.js (Section 12 scheme B).

CAB TYPE / MIC TYPE: non-standard, require lookup tables. See Section 8.

32-BIT VALUES in TFX body (amp model, cab type raw): signed int32,
  little-endian in the body's 8-byte key/value pairs. Amp model also appears
  as a 32-bit selector in some CMD 0x11 contexts assembled big-endian
  (v0<<24|v1<<16|v2<<8|v3). Use the integer maps in Section 12.

===================================================================
9. TUNER
===================================================================

SOFTWARE SEND: CC 69 (0x45).  ON = B0 45 7F   OFF = B0 45 00.

HARDWARE READBACK: the hardware does NOT echo CC 69. It responds with a
SysEx CMD 0x40 broadcast (corrected 7/15):
  F0 13 0B 0F 02 40 [state] F7      state: 0x01=ON, 0x00=OFF
CMD 0x41 fires as a companion broadcast — safe to ignore.
Handler lives in sysex-handler.js. (Reconciles with C6.)

(Raw-USB research also documented a tuner-data polling path — REQU 0x41/0x42
returning note/cents — used by the Avid editor's tuner graphic. Not used by
Eleven Edit; retained here for completeness. Tuner reading: RESP
F0 13 0B 04 0F 12 42 07 [note] [tune] F7; note low-nibble=note 0=C..11=B,
high-nibble=octave; tune 0=in tune.)

10. STEREO / MONO
===================================================================

TFX key: RMno (global section). 0=Stereo, 1=Mono.
Live broadcast: CMD 0x0D — F0 13 0B 0F 02 0D 06 [val] F7,

UI: indicator badge on the chain row; dim when Stereo, lit amber when Mono.

13. TFX BINARY FORMAT
===================================================================

A .tfx file = [56-byte header] + [body]. Body == decode7bit(SEND_PATCH
payload). A 968-byte body -> 1024-byte file. All sources (Avid Editor,
ElevenHack, Eleven Edit, HW save) produce SHA-256 identical files for the
same patch content.

56-BYTE HEADER:
  bytes 0–3   total file size, big-endian uint32 (e.g. 0x00000400 = 1024)
  bytes 4–7   zeros
  bytes 8–23  magic "DigiElvRELVhRig " (16 bytes, space-padded)
  bytes 24–55 zeros
  Load compatibility check: magic begins "DigiElv" at offset 8.

BODY LAYOUT:
  bytes 0–3   version quadlet
  bytes 4–7   signature/headerCode (changes when content changes)
  bytes 8–35  rig name, 7 quadlets (reversed byte order per quadlet)
  byte 36+    TOC / global params, then per-effect sections

KEY ENCODING ("quadToKey"): read 4 raw bytes, reverse to get the key name.
  e.g. raw 0x36 0x64 0x6C 0x73 reversed = "6dls" (amp model marker);
       raw 0x37 0x64 0x6C 0x73 reversed = "sld7".
  Every key is immediately followed by its 4-byte little-endian value
  (8-byte pairs). Key search scans the whole body, so it is position-
  independent and works regardless of chain order.

VALUE ENCODING (continuous knobs — gate, amp out, rig vol, tone, breakup):
  Signed 32-bit int, linear across the full int32 range.
  INT32_MIN (0x80000000) = 0% ; INT32_MAX (0x7FFFFFFF) = 100%.
  To 0–127: Math.round((signed - (-2147483648)) / 4294967295 * 127).
  Helper gateRawToV127(signed) does this.

TOGGLES in TFX body (e.g. Bright): raw 0=OFF, 1=ON. Do NOT run through
gateRawToV127 (which would map 0 to the midpoint 64). Use: signed !== 0 ? 127 : 0.

7-BIT DECODE (protocol.js — the trusted version):
  function decode7bit(enc){
    const res=[]; let begin=0,shift=1,i=0,len=enc.length;
    while(begin+i<len-1){
      let v=(((enc[begin+i]&0xFF)<<shift)&0xFF)+(((enc[begin+i+1]&0xFF)>>(7-shift))&0xFF);
      res.push(v&0xFF); shift++;
      if(shift===8){shift=1;begin++;} i++;
    }
    res.push(((enc[len-1]&0xFF)<<shift)&0xFF);
    return res;
  }
7-BIT ENCODE: use ONLY the encode7bit in protocol.js. encode7bit(968-byte
body) must produce exactly 1107 bytes. ElevenHack's encode7bit does NOT
correctly invert this decode — do not use it (causes "Bad Patch Data").

===================================================================
15. SAVE PROTOCOL (software-initiated commit to slot)
===================================================================

STATUS: implemented ("Save to Current Slot"). Each step uses a DIFFERENT
addressing format:
  Step  Cmd     Format                          Example (slot 4 = B1)
  1     0x05    name (plain ASCII)              F0 13 0B 0F 00 05 [name] 00 F7
  2     0x03    [raw_slot] [0x00]               F0 13 0B 0F 00 03 04 00 F7
  3     0x04    [bank] [num] [name] [00]        F0 13 0B 0F 00 04 01 00 [name] 00 F7
  4     0x02    [0x00] [raw_slot]               F0 13 0B 0F 00 02 00 04 F7
  raw_slot = 0–103, bank = floor(slot/4), num = slot%4.

Hardware responds with dirty-flag clear, slot confirm, full bulk broadcast.
SAFETY NOTE: software save does NOT trigger the hardware-save auto-export
(the CMD 0x04 echo arrives AFTER the bulk broadcast in software save, but
auto-export detection needs it BEFORE).
NOT YET: save-to-different-slot (slot picker), rename-on-save.


===================================================================
16. LOAD TFX PROTOCOL (file -> hardware memory)
===================================================================

STATUS: implemented ("Load TFX"), round-trip verified.
  Step 1 — bulk write (memory only, does NOT commit to a slot):
    F0 13 0B 0F 00 01 [encode7bit(body)] F7
    body = TFX file minus the 56-byte header. encode7bit(968) -> 1107 bytes.
  Step 2 — name write:
    F0 13 0B 0F 00 05 [ASCII name] 00 F7
Hardware echoes bulk data back as ASYNC (dir=0x02, cmd=0x01); the SEND_PATCH
handler decodes it (payload at position 6). Load accepts any file with
"DigiElv" magic at offset 8. Round-trip: capture -> save -> load -> capture
-> SHA-256 matches.


===================================================================
17. BANK BACKUP / RESTORE (EHB format)
===================================================================

Not yet implemented; protocol fully known. EHB = a standard ZIP of 104 TFX
files, one per slot. No proprietary format, no encryption.
  Filename inside ZIP: [Letter][Number]-[PatchName].tfx (e.g. A1-DC Vintage
  Crunc.tfx). Unused slots: "-unused-.tfx" (default empty patch).
BANK SAVE (HW -> file): for each slot: CURR_RIG to slot -> REQU SEND_PATCH ->
  hardware streams body back -> strip, decode7bit, prepend 56-byte header ->
  write .tfx. (RIG_GETNAME via CMD 0x04 is a cheaper names-only scan.)
BANK RESTORE (file -> HW): per slot, run the Load (Section 16) + Save
  (Section 15) sequence. ~104 cycles; several minutes with per-slot verify.

RIG VOLUME: CC 17 sends (all amps). CMD 0x07 live readback. REQU RIG_VOL
reads current. Range val=0 -> -24.0 dB, val=127 -> 0.0 dB. Note: the Rig

  F0 13 0B 0F 00 36 04 [slot] [v0] 00 04 00 00 00 05 F7
  To Amp 1 slot=0x02, To Amp 2 slot=0x03. Standard (v127+64)%128 encoding.

22. FLAGGED CONFLICTS
===================================================================

C1 — 0x04 FRAMING (RESOLVED). Old raw-USB research (node-usb / Wireshark)
  shows a 0x04 device byte in the header (F0 13 0B 04 0F) and a 0x04 marker
  before every 3 payload bytes. The Java-bridge MIDI path does NOT: the app
  sees clean F0 13 0B 0F with no framing. Both are correct for their own
  layer. Application code must never add/strip 0x04. Separately, the 0x04 at
  data[6] of CMD 0x11 FORMAT B is real SysEx, unrelated to USB framing.

C2 — REQUIRED DRIVER VERSION (RESOLVED). v1.1.12 is confirmed as the working
  driver for the Java-bridge build. The v1.0.11 requirement (and the v1.1.16
  "locks hard" note) came from the abandoned node-usb path, which claimed the
  raw USB interface; the Java-bridge path goes through the OS MIDI layer and
  works on the newer, fully featured v1.1.12. Use v1.1.12.

C3 — paramLo VALUES ABOVE 0x0F (RESOLVED, newer wins). The June research
  derived paramIds from Avid XML sldX letters (sldF=0x0F, sldG=0x10), which is
  WRONG above sld9. Wireshark (7/15) confirms sldF=0x10 and sldG=0x11. Several
  per-amp assignments in the June table were also wrong (e.g. Lead 800 and DC
  family Master/Gain/PreAmp swaps). Section 11 (Wireshark-confirmed) is
  authoritative; the June per-amp paramId table is superseded in full.

C4 — MIC AXIS v0 DIRECTION (RESOLVED). On-Axis=0x3F, Off-Axis=0x40 — confirmed
  from the Avid editor walk capture AND working in the current build. The 7/14
  value (On-Axis=0x40) was inferred before a real capture existed and was wrong.
  Document and code agree. (TFX key sldM is separately 0=Off-Axis, 1=On-Axis.)

C5 — AMP BYPASS paramLo. June research: 0x01 (from the wrong XML derivation).
  Confirmed value: 0x06 (live only; REQU returns nothing). Use 0x06.

C6 — AMP TYPE / AMP SELECT paramLo. June research: 0x03 = amp/cab type
  selector. Confirmed: 0x03 = Amp Out Level; Amp Select = 0x0F (raw v0). Use
  0x0F for selecting the amp, 0x03 for Amp Out.

C7 — TUNER READBACK. Reference 07-14 implied a CC-based tuner confirm
  (0x40/0x3F). 7/15 confirmed the hardware does NOT echo CC 69; it broadcasts
  CMD 0x40 SysEx (01=ON/00=OFF). Send is still CC 69. Use CMD 0x40 for readback.

C8 — SLOT/BANK ARITHMETIC. Most docs: bank=floor(slot/4), num=slot%4 (4 slots
  per bank, 26 banks). Primer note gives bank=floor(slot/24), rig=slot%24.
  The /4 grouping matches the A1–Z4 labeling used everywhere else and the save
  protocol; treat /4 as authoritative unless a specific feature proves otherwise.

C9 — TRUE Z "AUTO" VALUE. Live CMD 0x34 broadcast uses 0x00 (older) / 0x7E
  (raw-USB capture) for Auto; the TFX PIGI field uses 125. These are different
  representations on different paths, not a single value. True Z is receive-
  only and non-core; note but no action needed.
